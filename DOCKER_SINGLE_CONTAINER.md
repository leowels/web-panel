# 🐳 Деплой Frontend + Backend в одном Docker контейнере

## ✅ Преимущества

- ✅ Один контейнер вместо двух
- ✅ Проще управление
- ✅ Меньше ресурсов
- ✅ Проще настройка

## 📋 Что нужно сделать

### 1. Использовать Dockerfile.full

В Timeweb Cloud при создании приложения укажите:
- **Dockerfile:** `Dockerfile.full` (вместо `Dockerfile`)

### 2. Настроить переменные окружения

В одном контейнере нужно настроить переменные для обоих сервисов:

```env
# Frontend
NODE_ENV=production
PORT=3000
NEXT_PUBLIC_API_URL=http://localhost:8000

# Backend
SECRET_KEY=<сгенерируйте_ключ>
DATABASE_URL=postgresql://user:password@host:5432/dbname
CORS_ORIGINS=https://yourdomain.com
ENVIRONMENT=production
ADMIN_PASSWORD=<сильный_пароль>

# AI (опционально)
AI_PROVIDER=timeweb
AI_API_KEY=<ваш_ключ>
AI_BASE_URL=<url_вашего_агента>
AI_AGENT_ACCESS_ID=<access_id>
```

### 3. Настроить порты

В Timeweb Cloud настройте:
- **Порт 3000** - для Frontend (основной)
- **Порт 8000** - для Backend (внутренний)

Или используйте один порт 3000, а Backend будет доступен через внутренний порт.

### 4. Важно про CORS

Если Frontend и Backend в одном контейнере:
- `NEXT_PUBLIC_API_URL` может быть `http://localhost:8000` (внутренний)
- `CORS_ORIGINS` должен содержать внешний домен: `https://yourdomain.com`

## 🔧 Альтернативный вариант: Nginx как reverse proxy

Можно использовать Nginx для маршрутизации:

```
Frontend (Next.js) -> порт 3000
Backend (FastAPI) -> порт 8000
Nginx -> порт 80/443 -> маршрутизирует запросы
```

Но для простоты можно использовать один порт 3000 для Frontend, а Backend будет доступен через проксирование или внутренний порт.

## 📝 Обновленный план деплоя

### Шаг 1: Подготовка
```bash
git add Dockerfile.full docker-entrypoint.sh
git commit -m "feat: добавлен единый Dockerfile для Frontend + Backend"
git push
```

### Шаг 2: Создание приложения в Timeweb Cloud
- Тип: Docker контейнер
- Dockerfile: `Dockerfile.full`
- Порт: 3000 (основной)

### Шаг 3: Настройка переменных окружения
Добавьте все переменные из раздела выше.

### Шаг 4: Настройка базы данных
Создайте PostgreSQL базу данных и укажите в `DATABASE_URL`.

### Шаг 5: Запуск
Запустите сборку и дождитесь завершения.

## ⚠️ Важные замечания

1. **Порты:** Оба сервиса работают в одном контейнере, но на разных портах
2. **Масштабирование:** Сложнее масштабировать отдельно Frontend и Backend
3. **Ресурсы:** Один контейнер потребляет больше ресурсов
4. **Отказоустойчивость:** Если один сервис упадет, может упасть весь контейнер

## 🎯 Рекомендация

Для production лучше использовать **два отдельных контейнера**:
- Легче масштабировать
- Можно обновлять независимо
- Лучше отказоустойчивость

Но для начала или небольших проектов **один контейнер** - отличное решение!
